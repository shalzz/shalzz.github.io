Plus since there’s no longer a SIM card required to be tethered to a single device, we can make and receive calls across multiple devices.</p> <p>This also mitigates the ever-growing threat of SIM swap attacks. Both, physical attacks as the SIM card associated with your number is no longer required to be always in your phone, and operator social engineering attacks since most VOIP providers have a higher security level than most traditional telecom providers.</p> <h2 id="asterisk-pbx-server"><a class="zola-anchor" href="#asterisk-pbx-server" aria-label="Anchor link for: asterisk-pbx-server">🔗</a> Asterisk PBX Server</h2> <p>While the regulation of some countries like the US allows buying a consumer feature level number from a VOIP provider like <a rel="noopener nofollow noreferrer external" target="_blank" href="https://www.twilio.com/">Twilio</a> with unrestricted functionality for calls and SMS/MMS. The feature set starts to degrade drastically from what we are used to when buying local numbers for most other countries.</p> <p>If you are following this guide with a US number or any other country that allows first-class support to VOIP providers then you can skip this section on setting up an Asterisk server.</p> <p>If however you find yourself with a number from a country that restricts VOIP providers from providing full feature-set local numbers then we can circumvent that via a 3G/4G USB dongle with voice calling support. This allows us to then bring up a PBX server connected to the internet with the ability to route traditional PBX calls via the USB dongle holding your own local number SIM card.</p> <p>The first step is to then install an <a rel="noopener nofollow noreferrer external" target="_blank" href="https://www.asterisk.org/">Asterisk</a> server on a machine that can be left running 24/7 for maximum uptime. This guide uses OpenWRT OS and packages in examples but you can use any machine you have lying around including a Raspberry Pi.</p> <p>With an already set up OpenWRT router, you’ll need the following packages to install Asterisk:</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="shellscript"><span class="giallo-l"><span style="color: #268BD2;">opkg</span><span style="color: #2AA198;"> install Asterisk Asterisk-pjsip Asterisk-bridge-simple Asterisk-codec-alaw Asterisk-codec-ulaw Asterisk-res-rtp-Asterisk Asterisk-res-srtp Asterisk-chan-dongle</span></span></code></pre><h3 id="asterisk-chan-dongle"><a class="zola-anchor" href="#asterisk-chan-dongle" aria-label="Anchor link for: asterisk-chan-dongle">🔗</a> Asterisk-chan-dongle</h3> <p>Now comes the tough part of acquiring and setting up a USB dongle. We’re using <a rel="noopener nofollow noreferrer external" target="_blank" href="https://github.com/wdoekes/asterisk-chan-dongle">wdoekes/Asterisk-chan-dongle</a> an Asterisk channel driver for interfacing with the USB dongle from the Asterisk server.</p> <p>The tricky part here is that the channel driver doesn’t work with every 3G/4G USB dongle, only Huawei 3G dongles and a few 4G dongles. And even with the dongles that it does work, not every supported dongle has voice support available or firmware unlocked.</p> <p>The best way is to look at the list of supported dongles on the project’s <a rel="noopener nofollow noreferrer external" target="_blank" href="https://github.com/wdoekes/asterisk-chan-dongle#chan_dongle-channel-driver-for-huawei-umts-cards">README</a> file and try to get your hands on one of them. I bought an E1750 Huawei 3G dongle which you still find in stock in many online stores. If it’s unavailable in your local markets/ e-commerce sites, try searching it on eBay or AliExpress. I was able to get a second-hand one from eBay with SIM and voice support unlocked.</p> <p>Once you have a dongle, insert your SIM card and plug it into the machine you have Asterisk installed. Make sure you have the <code>asterisk-chan-dongle</code> package installed.</p> <p>To configure, we edit the <code>dongle.conf</code> file found in the configuration folder of Asterisk. The configuration folder is defined via the <code>astetcdir</code> option in the main <code>asterisk.conf</code> file and is usually <code>/etc/asterisk/</code>.</p> <p>If there’s no <code>dongle.conf</code> file located in the configuration folder, create one. The default dongle.conf can be found <a rel="noopener nofollow noreferrer external" target="_blank" href="https://github.com/wdoekes/asterisk-chan-dongle/blob/master/etc/dongle.conf">here</a>.</p> <p>Make a note of the <code>context</code> option in <code>dongle.conf</code>, the default value of <code>context</code> is <code>default</code> which we’ll be referencing later. You can change it to something more appropriate like <code>dongle-incoming</code> to make it easier to remember, which is what we’re doing in the below example.</p> <p>The main configuration requirements are specifying the correct audio and data device ports of the dongle.</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="ini"><span class="giallo-l"><span>[dongle0]</span></span> <span class="giallo-l"><span style="color: #859900;">context</span><span> = dongle-incoming</span></span> <span class="giallo-l"><span style="color: #859900;">audio</span><span> = /dev/ttyUSB1 </span><span style="color: #93A1A1;font-style: italic;">; tty port for audio connection; no default value</span></span> <span class="giallo-l"><span style="color: #859900;">data</span><span> = /dev/ttyUSB2 </span><span style="color: #93A1A1;font-style: italic;">; tty port for AT commands; no default value</span></span></code></pre> <p>The exact value here will depend on your dongle and the distribution you’re running. You might need to install the <code>usb_modeswitch</code> package to switch the dongle from the initial CD-ROM/mass storage mode to the serial mode. You should then be able to start the Asterisk server and watch the logs for errors. Make sure there are no dongle-related errors.</p> <p>Note: To enable logging you might need to edit <code>logger.conf</code> to increase the log level. (You can find the <code>messages</code> log file in the <code>astlogdir</code> folder) :</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="plain"><span class="giallo-l"><span>console =&gt; notice,warning,error</span></span> <span class="giallo-l"><span>messages =&gt; notice,warning,error,debug</span></span></code></pre> <p>Check the status of your dongle and network registration via these two commands in the Asterisk console. (You can attach a console to a running Asterisk server via the command <code>asterisk -r</code>)</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="plain"><span class="giallo-l"><span>dongle show devices</span></span> <span class="giallo-l"><span>dongle show device state dongle0</span></span></code></pre> <p>If the output shows the device state as “Free”, then you’re good to go.</p> <h3 id="sms-forwarding-optional"><a class="zola-anchor" href="#sms-forwarding-optional" aria-label="Anchor link for: sms-forwarding-optional">🔗</a> SMS Forwarding (Optional)</h3> <p>The easiest and simplest way to get acquainted with Asterisk and how to configure it is to set up SMS forwarding from our USB 3G dongle to an email ID.</p> <p>We can do so by editing <code>extensions.conf</code>. The file is already well documented via comments (any line preceded by <code>;</code> is a comment and is ignored).</p> <p>Append the following lines at the end of the file to set up SMS forwarding.</p> <pre class="giallo" style="color: #657B83; You can read more about how <a rel="noopener nofollow noreferrer external" target="_blank" href="https://wiki.asterisk.org/wiki/display/AST/Contexts%2C+Extensions%2C+and+Priorities">Context, Extensions, and Priorities</a> work in Asterisk from their wiki.</p> <p>Once we craft an email message we defer to a sendmail compatible SMTP client to send the email. This example uses <code>msmtp</code> here, you can instead use any other client and configure it accordingly.</p> <p>The above extension configuration calls a few Asterisk built-in apps and functions that you might need to install separately. For OpenWRT install the following packages:</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="plain"><span class="giallo-l"><span>opkg install asterisk-app-system asterisk-app-verbose asterisk-func-base64</span></span></code></pre> <p>If you just want SMS forwarding to your email and don’t care about PSTN voice calls then congratulations you should have SMS-to-email forwarding working at this point. If you want voice call functionality as well, continue reading.</p> <h3 id="configuration"><a class="zola-anchor" href="#configuration" aria-label="Anchor link for: configuration">🔗</a> Configuration</h3> <p>Once we have everything installed and running, it’s time to configure our Asterisk PBX server to do two things:</p> <ol> <li>Set up call extensions so that Asterisk knows how and where to route incoming and outgoing calls</li> <li>Authenticate and interface with Twilio as a BYOC trunk</li> </ol> <p>While we don’t need to use Twilio or a VOIP service provider to act as a proxy for our PBX server, using one adds a level of security and reliability to our setup as we don’t need to whitelist dynamic IP addresses for communicating with a mobile softphone and Twilio’s global presence and edge locations enable much better performance and reliability than just directly talking to our home Asterisk server from across the globe.</p> <p>The configuration shared here are just minimal examples that should work for most cases, you may have to tweak and adjust them to suit your setup and requirements.</p> <p>There are a few files that we’ll need to edit mainly, <code>pjsip.conf</code>, <code>pjsip_wizard.conf</code> and <code>extensions.conf</code></p> <p>The first thing that we need to do is set up a “transport” for Asterisk to use for SIP signaling in the <code>pjsip.conf</code> file:</p> <pre class="giallo" style="color: #657B83; background-color: #FDF6E3;" ><code data-lang="ini"><span class="giallo-l"><span>[transport-udp]</span></span> <span class="giallo-l"><span style="color: #859900;">type</span><span>=transport</span></span> <span class="giallo-l"><span style="color: #859900;">protocol</span><span>=udp</span></span> <span class="giallo-l"><span style="color: #859900;">bind</span><span>=0.0.0.0:5060</span></span></code></pre> <p>The next step is connecting our PBX to Twilio as a Trunk using their BYOC Trunk option.
